# Наръчник за GitHub

## 📋 Качване на НОВ проект в GitHub

### Стъпка 1: Подготовка на Git (Еднократно)
Ако вече сте го направили, пропуснете тази стъпка.

```bash
git config --global user.email "вашият-email@example.com"
git config --global user.name "Вашето Име"
```

### Стъпка 2: Създаване на Repository в GitHub
1. Отидете на: **https://github.com/new**
2. Въведете име на проекта
3. **НЕ** добавяйте README, .gitignore или license
4. Натиснете "Create repository"
5. **Копирайте URL адреса** (ще изглежда така: `https://github.com/username/project-name.git`)

### Стъпка 3: Инициализиране на Git в проекта
Отворете папката на проекта във VS Code и изпълнете:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/username/project-name.git
git push -u origin main
```

## 🔧 Основни Git команди и тяхното значение

| Команда | Какво прави |
|---------|-------------|
| `git status` | Показва текущото състояние (променени файлове) |
| `git add .` | Подготвя ВСИЧКИ променени файлове за commit |
| `git add файл.txt` | Подготвя КОНКРЕТЕН файл за commit |
| `git commit -m "съобщение"` | Запазва промените ЛОКАЛНО на компютъра |
| `git push` | Изпраща commit-ите към GitHub (онлайн) |
| `git pull` | Изтегля промени от GitHub към компютъра |
| `git log` | Показва история на commit-ите |

## 💡 Три начина за работа с Git

### Вариант 1: VS Code Source Control панел (Най-лесно)
1. Натиснете иконата **Source Control** от лявата страна (трета икона, като разклонение)
2. Виждате променените файлове
3. Натиснете **"+"** до файла за Stage (или "+" до Changes за всички)
4. Напишете съобщение в полето **"Message"**
5. Натиснете бутона **"Commit"** (✓)
6. Натиснете бутона **"Sync Changes"** или **"Push"** за качване в GitHub

### Вариант 2: VS Code Терминал (Директно)
1. Отворете терминала: **`Ctrl + ` `** (backtick) или `View → Terminal`
2. Напишете командите:
```bash
git add .
git commit -m "описание на промяната"
git push
```

### Вариант 3: Чрез GitHub Copilot Chat
Просто напишете в чата:
- "Направи commit с това съобщение"
- "Качи промените в GitHub"
- Copilot ще изпълни командите вместо вас

## 🔄 Типичен работен процес

```
1. Редактирате файлове в проекта
2. Запазвате (Ctrl + S)
3. git add . (подготовка)
4. git commit -m "какво направих" (локално запазване)
5. git push (качване в GitHub)
```

**Кратко:**
- **Commit** = Запазване на компютъра
- **Push** = Изпращане в GitHub (облака)

## 📁 Как да създам НОВ, отделен проект

За **всеки нов проект**:

1. **Създайте НОВА папка** (извън текущия проект)
2. **Отворете папката** във VS Code (`File → Open Folder`)
3. **Създайте файловете** на новия проект
4. **Повторете стъпките** от "Качване на НОВ проект в GitHub" по-горе
5. **Важно:** Създайте НОВ repository в GitHub с друго име

**Всяка папка = Отделен Git repository = Отделен GitHub проект**

## ⚠️ Полезни съвети

- Правете commit често (след всяка завършена задача)
- Пишете ясни съобщения за commit ("Поправих бъг в калкулатора", не "update")
- Push-вайте поне веднъж дневно за backup
- Преди да започнете работа, направете `git pull` (ако работите от няколко компютъра)

## 🧩 Как да отделя голяма версия (пример: V3), без да счупя `main`

Това е полезно, когато правите големи промени и искате старото стабилно състояние да остане в `main`.

### Вариант A: Отделяне чрез branch (препоръчително)

1. Създай и премини към нов branch:
```bash
git checkout -b v3
```

2. Работи нормално (edit → `git add .` → `git commit -m "..."`).

3. Push-ни branch-а към GitHub:
```bash
git push -u origin v3
```

4. В GitHub:
- `main` остава стабилен
- `v3` съдържа новите промени
- Може да се правят Pull Requests от `v3` към `main` само когато сте готови

### Вариант B: Отделяне в напълно нов GitHub repository (когато е „нова версия/продукт“)

Ако V3 трябва да е отделен проект (други потребители/друга история), може да се направи нов repo.

1. Създай нов repository в GitHub (без README/.gitignore/license).

2. В проекта локално добави втори remote (примерно `v3origin`):
```bash
git remote add v3origin https://github.com/<username>/<new-repo>.git
```

3. Push-ни текущия branch към новия repo:
```bash
git push -u v3origin v3
```

### Ако по грешка push-неш „големи промени“ в `main`

Най-сигурният вариант е да върнете `main` към стария стабилен commit и да държите новата версия в branch/repo.

1. Намери commit-а, към който искаш да върнеш `main`:
```bash
git log --oneline
```

2. Върни `main` локално към него (ВНИМАНИЕ: променя историята на `main`):
```bash
git checkout main
git reset --hard <stable_commit_hash>
```

3. Push-ни форсирано към GitHub (само ако сте сигурни, че това е правилният ход):
```bash
git push --force origin main
```

4. Провери, че новата работа е запазена (в branch, или в отделния repo).
