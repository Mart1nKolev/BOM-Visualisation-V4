### Стъпка 3: Функция `getLevel1Assemblies()`

**Действие:** Добавена функция след `findAssemblyByPath()`
```javascript
function getLevel1Assemblies() {
    const level1Assemblies = [];
    
    bomData.objects.forEach(obj => {
        if (obj.flatBOM && obj.flatBOM.length > 0) {
            obj.flatBOM.forEach(item => {
                if (item.level === 1) {
                    level1Assemblies.push({
                        path: item.path,
                        cleanName: item.name,
                        objectName: obj.name,
                        quantity: item.quantity || 1
                    });
                }
            });
        }
    });
    
    return level1Assemblies;
}
```

**Резултат:** ✅ Wizard се отваря успешно!

### Проблем: Вместо имена се показва `<подасембли>`

**Причина:** BOM данните съдържат `<подасембли>` като име вместо реално име на сборката

**Анализ в конзолата:**
```
Намерена сборка по точен път: 30_03_S1 (ALL Bufer Service Komplekt)
✅ Намерена сборка по точен път: <подасембли> (ALL Bufer Service Komplekt/Planka Bufer Komplekt<1>)
✅ Намерена сборка по точен път: <подасембли> (ALL Bufer Service Komplekt/.../M8x20 Komplekt<1>)
```

**Решение:** Извличане на име от пътя (`path`)
- Взимаме последната част: `path.split('/').pop()`
- Премахваме `<1>`, `<2>` и т.н.: `replace(/<\d+>$/, '')`
- Пример: `Planka Bufer Komplekt<1>` → `Planka Bufer Komplekt`

---

### Стъпка 4: Поправка на `findAssemblyByPath()`

**Действие:** Добавена вътрешна функция `extractNameFromPath()` и логика за проверка:
```javascript
function extractNameFromPath(path) {
    const lastPart = path.split('/').pop();
    return lastPart.replace(/<\d+>$/, '');
}

// Ако името е <подасембли>, използвай пътя
let displayName = item.name;
if (!displayName || displayName === '<подасембли>' || displayName.trim() === '') {
    displayName = extractNameFromPath(item.path);
}
```

**Резултат:** ✅ Таб "🏭 Сглобяване" показва реални имена!

### Проблем: CORS грешка в конзолата при зареждане

**Грешка:**
```
Access to fetch at 'file:///C:/get_user_data' from origin 'null' has been blocked by CORS policy
```

**Причина:** При отваряне на file:// протокол, `detectSharedMode()` прави fetch към `/get_user_data`, което браузърът блокира

**Решение:** Проверка на протокола ПРЕДИ fetch
```javascript
if (window.location.protocol === 'file:') {
    isSharedMode = false;
    console.log('📱 Локален режим - файлът е отворен директно (file://)');
    return; // БЕЗ fetch!
}
```

**Резултат:** ✅ Без червени грешки в конзолата!
